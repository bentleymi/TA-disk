=== SUMMARY (full, listing Summary tab) ===
Collects disk health from smartctl (SATA/ATA SMART + NVMe) and /sys/class/nvme: health status, power-on hours, temperature, NVMe wear (percentage used, available spare), media errors and SMART raw counters (reallocated, uncorrected, CRC). Emits per-disk JSON events to index=main (sourcetype disk:status) and numeric disk.<device>.<attribute> metrics to index=metrics (sourcetype disk:metrics), with overview and metrics dashboards.

=== DETAILS ===
Events: index=main sourcetype=disk:status  (per-disk JSON: model, serial, firmware,
health, temperature, power_on_hours, percentage_used, available_spare, media_errors, raw counters)
Metrics: disk.<device>_<attribute> on index=metrics
Dashboards: TA-Disk > Disk Overview / Disk Metrics

=== INSTALLATION ===
Install on each monitored host (Apps > Install app from file,
splunk install app, or deployment server), restart Splunk, then verify:

  index=main sourcetype="disk:status" | head
  | mcatalog values(metric_name) where index=metrics metric_name="disk.*" by host

The dashboards require a metrics-typed index (metrics datatype=metric).

=== TROUBLESHOOTING ===
- If no data: verify smartctl is installed and the Splunk service can run it (splunkd runs as root or the splunk user; SMART needs read access to /dev/block devices).
- Read-only filesystem or non-SMART disks (virtio) are skipped gracefully.
- NVMe wear fields exist only on NVMe devices; SATA disks emit SMART raw counters instead.
